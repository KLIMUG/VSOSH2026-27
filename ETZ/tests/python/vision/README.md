# Распознавание поля и шашек — рабочая база

Только скелет: привязка кадра к миллиметрам поля и заготовка поиска шашек.
Цвета, стопки и логику задач дописываешь сам.

## Установка

```bash
pip install opencv-contrib-python numpy
```

`opencv-contrib-python`, а не `opencv-python`: модуль `cv2.aruco` есть только в contrib.
Готовый venv уже лежит в `python/venv`, но запускать лучше из него же после установки:

```bash
python/venv/bin/python.exe -m pip install opencv-contrib-python numpy
```

## Файлы

| Файл | Что внутри |
| --- | --- |
| `field.py` | чтение меток `DICT_4X4_50` (id 27/28/29), `пиксели → мм`, `мм → клетка` |
| `pieces.py` | скелет поиска шашек цветом по HSV (`TODO` — твои диапазоны) |
| `main.py` | запуск: камера или один кадр, отрисовка найденного |

## Запуск

```bash
cd ETZ/tests/python/vision
python main.py            # камера 0
python main.py 1          # внешняя USB-камера
python main.py foto.png   # разбор одного снимка
```

В консоли печатается строка вида `метки=[27, 28] невязка=0.83 шашек=3`.
ESC — выход, `S` — сохранить кадр в `snapshot.png`.

## Что проверить первым делом

1. **`MARKERS_MM` в `field.py`** — координаты центров меток в мм на твоём листе.
   Значения по ЕТЗ, но линейкой проверь: ошибка здесь сдвигает всю картину.
2. **Невязка.** `невязка` больше ~1.5 мм — значит метки напечатаны повёрнуто
   относительно осей клеток, кадр зеркален или лист сильно наклонён к камере.
   Разворот лечится порядком `CORNER_SIGNS`.
3. **Разрешение.** Модуль метки (18/6 ≈ 3 мм) должен быть ≥ 3–4 px:
   640 px по ширине кадра мало, бери 1280×720 и выше.
4. **HSV-диапазоны** в `pieces.py` — единственное, что придётся подбирать руками.
   Открой `color_mask()` в отдельном окне при разном свете полигона.
5. **`MIN_AREA`/`ROUNDNESS`** — пересчитай под свой масштаб (26 мм шашка при
   ~2 px/мм даёт ~50 px диаметра, площадь ~2000 px).

## Чего здесь намеренно нет

- склейки дублей от красного (он всегда режется на два диапазона);
- разбора стопок (на ЗЭ нижняя шашка задаёт положение, верхняя — цвет);
- калибровки камеры и компенсации перспективы (сейчас `estimateAffinePartial2D`
  компенсирует только поворот/масштаб/сдвиг; при съёмке под углом переходи
  на `cv2.findHomography` по тем же углам меток).

## Куда дальше

`field.py` уже отдаёт `(X, Y)` в мм поля и имя клетки — это готовый интерфейс
для прошивки: список `(клетка, цвет)` можно гнать по UART на RP2040.
Дальше по вкусу: подобрать HSV, добавить стопки, вывести стабильный список
в JSON для контроллера.
